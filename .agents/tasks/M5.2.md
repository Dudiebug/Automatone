# M5.2 — Minimal one-screen GUI and block picker

## Metadata

- State: PLANNED
- Milestone: M5
- Depends on: INFERRED M5.1 scheduling edge; no explicit task-level dependency
  is stated by the plan.
- Risk: medium
- Sensor profiles: default, architecture_sensitive, runtime_minecraft
- Approved plan reference: plan lines 563-618.

## Objective

Provide one clear client screen with the planned worker controls and a
client-side searchable synchronized block picker that submits only a selected
registry ID.

## Why this task exists

The MVP needs one compact user surface after native mining and quantity
semantics have already passed. The GUI presents intent and server snapshots; it
does not discover blocks, mutate the world, or authorize actions.

## Allowed scope

- Worker identity, searchable picker, quantity, unlimited, Start, Stop.
- Current target, progress, status, and last error display.
- Client-side translated-name and registry-ID filtering over synchronized data.
- Selected registry-ID intent submission.

## Explicitly forbidden / out of scope

- Tabs, inventory dashboards, path visualizers, maps, logs, or storage controls.
- Client authority over state, progress, world mutation, or authorization.
- A second scanner, pathfinder, target queue, movement engine, or mining
  algorithm.
- Execution before Milestone 3 passes.

The mandatory shared rules are in INDEX.md#global-architecture-contract,
INDEX.md#quantity-semantics, INDEX.md#gui-gate-and-first-implementation-slice,
and INDEX.md#milestone-5-gate.

## Implementation constraints

- One screen only.
- Search synchronized registry data client-side.
- Send selected registry ID only; server validates it later in M5.3.
- Display server state; do not infer authoritative progress.
- Do not begin before the Milestone 3 gate.
