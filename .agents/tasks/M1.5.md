## Objective

Prove on a dedicated NeoForge server that a real server-side Automatone runtime
can be constructed, ticked, use the native MineProcess, cancel, dispose, and
be recreated without client or legacy runtime classes.

## Why this task exists

Compile and isolated lifecycle tests cannot establish that the real NeoForge
dedicated-server runtime loads and ticks correctly. This smoke slice is the
Milestone 1 integration gate before worker attachment begins.

resolves the repository's runtime tooling. An unavailable check remains

## Allowed scope

- Boot the dedicated server.
- Construct a server-side Automatone runtime.
- Retrieve the real getMineProcess().
- Tick for a bounded period.
- Activate and cancel a harmless process state.
- Dispose and recreate the runtime.
- Verify no client, Fabric, Quilt, or CCA class is required.

## Explicitly forbidden / out of scope

- Worker product logic, GUI, controller networking, quantity accounting, or
  persistence.
- A fake MineProcess or client-only fixture used to manufacture a pass.
- Client-only or fake-player infrastructure.
- Converting an unavailable GameTest/runtime command into PASS.
- GUI work before Milestone 3 passes.

The full global architecture contract, quantity semantics, and excluded-feature
list are preserved in INDEX.md.
