# M3.3 — Integrate cancellation with native Automatone mining

## Metadata

- State: PLANNED
- Milestone: M3
- Depends on: INFERRED M3.2 scheduling edge; no explicit task-level dependency
  is stated by the plan.
- Risk: critical
- Sensor profiles: default, architecture_sensitive, runtime_minecraft
- Approved plan reference: plan lines 373-432.

## Objective

Connect native Automatone break intent and MineProcess.cancel() to the worker
break controller so target changes and mid-break cancellation cannot complete
stale blocks.

## Why this task exists

The native process owns cancellation, while the worker controller owns the
server-side interaction state. The integration must cross that boundary exactly
once and clear held input/progress when native work is cancelled or retargeted.

This is required before the one-block proof can distinguish a real native
cancel from a merely visual or client-side stop.

## Allowed scope

- Worker IPlayerController methods used by native BlockBreakHelper.
- MineProcess.cancel() clearing worker held break/input state.
- Reset on native target changes.
- Mid-break cancellation test.

## Explicitly forbidden / out of scope

- A second consumer cancellation, pathing, scanner, target queue, or mining
  engine.
- Client animation or packet state as authority.
- GUI, quantity, persistence, storage, or networking product flow.
- GUI work before Milestone 3 passes.

The full global architecture contract, quantity semantics, and excluded-feature
list are preserved in INDEX.md.

## Preflight questions

1. Which MineProcess and BlockBreakHelper paths invoke IPlayerController?
2. Which cancellation callers and async publication paths can race with
   controller state?
3. Does the current controller already expose a reset/cancel hook?
4. Which server/main-thread boundary must own the mutation?
5. What GameTest observes native intent, cancel, retarget, and unfinished block?
6. Is any stale async behavior currently UNKNOWN?

## Implementation constraints

- Native MineProcess.cancel() remains the cancellation authority.
- Clear worker break/input state on the server.
- Reset old-target progress before accepting a new target.
- Do not let stale async calculations restart work.
- Keep all world mutation server authoritative.
