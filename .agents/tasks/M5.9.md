# M5.9 — Full worker inventories and inventory management

Authority: the human reports the M5 prerelease working flawlessly and requests
36-slot worker inventories, side-by-side player/worker inventories, Collect all,
and configurable automatic disposal of unwanted items. This supersedes the
nine-slot inventory requirement for this extension. No starter equipment remains.
Baseline: released `m5-preview-20260906` (`ba4db33d`), followed by the focused
death/unload roster repair `557bbd01` (24 affected GameTests PASS).

## Contract

- Every active and archived worker has 36 main slots: hotbar indices 0..8 and
  storage indices 9..35. Existing nine-slot saves retain their exact items and
  selected hotbar slot, with the additional slots empty. Normal save/reload,
  retirement, withdrawal, reactivation and dimension transfer preserve all slots.
- The inventory page shows the player's three rows plus hotbar on the left and
  the worker's matching layout on the right. Compact layouts keep every slot and
  action reachable. Native Minecraft slots retain ordinary click, shift-click and
  hotbar-swap behavior. Native Automatone retains tool selection and hotbar swaps.
- Collect all acts on the selected owned active/archived worker, transfers only
  what fits into the player's 36 inventory slots, and leaves overflow in the
  worker. It never drops or deletes overflow, inserts into an archive or transfers
  armor/offhand slots. Existing controller/menu/revision/pending-state checks apply.
- Automatic cleanup has an explicit per-worker enable switch, a configurable list
  of unwanted registered blocks, and a retained item count (default 64 per listed
  block item, editable 0..4096). It starts disabled for existing/new workers until
  the user enables it. Default list: dirt, cobblestone, cobbled deepslate, gravel,
  sand, red sand, netherrack, tuff, andesite, diorite and granite. Only those item
  types are candidates; tools, non-block items and stacks with custom components
  are protected. No inferred monetary/value ranking.
- When enabled, skip unwanted pickups beyond the reserve. If a wanted pickup
  cannot fit, eject only excess discard-listed stacks needed to make room, as real
  world ItemEntities. A rejected/cancelled entity spawn leaves the source stack
  unchanged. Never delete overflow or drop a retained reserve. Cleanup does not
  run while a native inventory menu is accessing the worker to avoid a moving
  slot during an in-progress click/drag; ordinary pickup remains server-owned.
- Protect the selected target blocks' item forms and item types observed in the
  actual BlockDropsEvent for those targets, including the final completion drop.
  Persist learned protection with that target set, retain it through pause/resume,
  completion and reload, and reset it only on a change of targets. Do not reroll
  loot, add a scanner/pathfinder, or replace native tool/hotbar management.
- Store policy/protection in worker entity NBT so retirement, reactivation,
  relocation and restart preserve them. Server validates policy edits via the
  existing controller/menu/owner/revision/pending guards. Policy changes do not
  restart the mining job. Policies belong to each worker in this first version.
- The existing batch job menu is unchanged by this task's inventory contract.

## Failure model and checks

1. Old save migration: slot 0 and slot 8 stacks/components/selection survive;
   slots 9..35 are empty. Full save/load preserves distinct items in 0, 8, 9, 35.
2. Archive persistence: retire a worker with storage-slot contents; withdraw from
   slot 35 and save/reload/reactivate; exact remaining stacks survive.
3. Real menu transfers: 72 distinct bound slots; clicks and shift-clicks work in
   both directions across the hotbar/storage boundary without changing total item
   counts. Archived slots reject insertion and cloning at every worker index.
4. Collect all: empty, partially filled and full player inventories; partial-stack
   merges, repeated requests and component-distinct items conserve items. Include
   storage slot 35. Deny absent controller, stale revision, wrong owner/menu and
   pending relocation with unchanged inventories.
5. Native inventory integration: a pickaxe placed only in worker storage can be
   moved to the hotbar and used by native mining. No second tool-selection engine.
   Cleanup checks cover keep-count boundaries, target/actual-drop/tool/custom
   protection, full inventory with collectible wanted drops, cancelled ejection
   with unchanged contents, no immediate recollection loop, policy/save/archive
   persistence and unauthorized/stale/pending policy requests.
6. Compile changed modules and run affected inventory/menu/roster/host/GameTests.
   Use existing deterministic fixtures; no mock inventory, ownership, slots, worker
   lifecycle or mining process. Existing network transport capture is allowed.
7. Use the repository proportional verification policy: one final independent
   extension gate from a clean candidate; no duplicate preliminary full profile,
   new dependency, mutation framework or coverage target. GPU layout/interaction
   acceptance remains manual and is recorded honestly.
