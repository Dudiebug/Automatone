# M3.2 — Implement real progressive destruction

## Metadata

- State: PLANNED
- Milestone: M3
- Depends on: INFERRED M3.1 scheduling edge; no explicit task-level dependency
  is stated by the plan.
- Risk: critical
- Sensor profiles: default, architecture_sensitive, runtime_minecraft
- Approved plan reference: plan lines 373-423.

## Objective

Make the worker controller perform real server-side progressive block
destruction using 1.21.1 rules, selected tools, durability, unbreakable
behavior, and normal destruction/drop hooks.

## Why this task exists

The generic dummy controller is insufficient for survival-like block breaking,
while a real player controller depends on ServerPlayer interaction management.
This task supplies only the focused non-player break contract required by
native Automatone.

World mutation and drops remain server authoritative. The consumer must not
predict loot or replace native discovery/pathing.

## Allowed scope

- Actual 1.21.1 block/tool destroy progress, not fixed timers.
- Unbreakable behavior.
- Actually selected worker tool.
- Appropriate durability/usage.
- Normal server-side destruction, loot/drop, and relevant hooks.

## Explicitly forbidden / out of scope

- Predicted loot injection into worker inventory.
- A custom Automatone scanner, pathfinder, target queue, movement engine, or
  mining algorithm.
- GUI, networking, quantity, persistence, storage, or worker fleet behavior.
- GUI work before Milestone 3 passes.

The full global architecture contract, quantity semantics, and excluded-feature
list are preserved in INDEX.md.

## Preflight questions

1. Which current BlockBreakHelper, ToolSet, and IPlayerController contracts
   are called by native break intent?
2. Which server API performs normal destruction and drops for a non-player?
3. Does the selected worker tool and durability path already exist?
4. Which vanilla/NeoForge hook and server-authority boundary is at risk?
5. What GameTest directly measures progressive speed, bedrock, durability, and
   drops?
6. Which exact 1.21.1 APIs remain UNKNOWN?

## Implementation constraints

- Use actual block/tool rules and server-side destruction hooks.
- Honor the worker's selected slot and actual tool.
- Keep world mutation on the server/main thread.
- Do not predict or inject loot.
- Native Automatone retains break intent, discovery, pathing, and cancellation.
