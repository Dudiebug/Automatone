# M6.3 — Add typed native failure reporting and user error mapping

## Metadata

- State: PLANNED
- Milestone: M6
- Depends on: INFERRED M6.2 scheduling edge; no explicit task-level dependency
  is stated by the plan.
- Risk: high
- Sensor profiles: default, architecture_sensitive, runtime_minecraft
- Approved plan reference: plan lines 759-782.

## Objective

Expose the smallest typed native/product termination vocabulary so the consumer
maps failures without parsing logs and preserves COMPLETED versus explicit
CANCELLED semantics.

## Why this task exists

User-facing failure must be stable and machine-readable, while native
MineProcess remains the authority for native failure logic. A narrow reason set
lets the consumer present errors without duplicating the process or scraping
logs.

## Allowed scope

- Listed native reason codes.
- Listed consumer error codes.
- Code/text separation.
- COMPLETED versus CANCELLED versus FAILED semantics.

## Explicitly forbidden / out of scope

- Consumer log parsing.
- Duplicated MineProcess failure logic.
- Unrelated reasons or speculative retries/queues.
- Client display text as authority.
- A second scanner, pathfinder, target queue, movement engine, or mining
  algorithm.

The mandatory shared rules are in INDEX.md#global-architecture-contract,
INDEX.md#explicitly-out-of-scope-through-milestone-6, and
INDEX.md#milestone-6-gate.

## Preflight questions

1. Which current MineProcess termination paths correspond to each native reason?
2. Which product/session symbols map native and consumer failures?
3. Does any existing consumer parse logs or conflate completion/cancellation?
4. Which native/consumer and code/text boundary is at risk?
5. What unit and runtime tests directly observe every listed code?
6. Are all termination paths known? If not, record UNKNOWN rather than invent
   a reason.

## Implementation constraints

- Add only the smallest typed observability needed.
- Keep native failure logic in Automatone.
- Keep codes machine-readable and display text separate.
- Map explicit Stop to CANCELLED and finite completion to COMPLETED.
- Avoid retries, queues, or duplicate native behavior.
