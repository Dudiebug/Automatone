# M4.4 — Quantity/cancellation GameTests

## Metadata

- State: PLANNED

  is stated by the plan.

## Objective

Provide the complete dedicated-server quantity and cancellation GameTest matrix
for finite, unlimited, obstruction, inventory, drop, and mid-break behavior.

## Why this task exists

The product quantity is source-block based and cancellation must stop native
work. This matrix makes the distinction observable across the plan's boundary
cases before controller/network work begins.

## Allowed scope

- Finite 1.
- Finite 3 of 5.
- Unlimited beyond 3.
- Cancel after first success.
- Cancel halfway through a slow block.
- Obstruction non-counting.
- Pre-existing matching inventory non-counting.
- Multi-drop/Fortune non-counting.

## Explicitly forbidden / out of scope

- Test-only duplicate scanner, pathfinder, target queue, movement engine, or
  mining algorithm.
- Scripted mining replacing native Automatone.
- GUI, networking, persistence, storage, retries, or excluded features.
- Weakening or deleting a valid failing test.

The mandatory shared rules are in INDEX.md#quantity-semantics,
INDEX.md#global-architecture-contract, and INDEX.md#milestone-4-gate.

## Preflight questions

1. Which product callbacks and native process state does each scenario observe?
2. Which test setup provides five targets, a slow block, obstructions, and
   controlled inventory/drops?
3. Does the current GameTest environment support those fixtures?
4. Which test could accidentally count items rather than source blocks?
5. What bounded observation window proves cancellation?
6. Are fixture paths or block setups UNKNOWN?

## Implementation constraints

- Use native Automatone for discovery, pathing, movement, and mining.
- Assert server-owned source progress only after actual destruction.
- Keep all scenarios deterministic and bounded.
- Preserve the exact listed cases.
- Mark unavailable runtime checks UNVERIFIED.
