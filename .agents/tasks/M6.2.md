# M6.2 — Define simple restart and unload semantics

## Metadata

- State: PLANNED
- Milestone: M6
- Depends on: INFERRED M6.1 scheduling edge; no explicit task-level dependency
  is stated by the plan.
- Risk: critical

  persistence
- Approved plan reference: plan lines 746-757.

## Objective

Make unload and restart safe: unloaded workers do no work, persisted RUNNING
tasks reload as INTERRUPTED, fresh transient runtimes are reconstructed, and no
work auto-resumes.

## Why this task exists

The MVP explicitly rejects chunk loading and unattended operation. Restart must
preserve understandable product state while discarding transient native
runtime/path state and requiring an explicit user Start.

## Allowed scope

- No work for unloaded workers.
- RUNNING to INTERRUPTED on persisted restart.
- One fresh transient runtime from current world state.
- No silent auto-resume; user Start required.
- Retain target, amount, and progress for manual restart.

## Explicitly forbidden / out of scope

- Chunk loading, offline mining, automatic resume/retry, job queues, or
  persistent pathfinding.
- Restored paths, nodes, scan generations, partial break progress, or active
  process internals.
- Client/UI resume authority.
- Duplicate scanner, pathfinder, movement engine, or mining algorithm.

## Implementation constraints

- Unloaded means no work; do not add chunk loading.
- RUNNING reloads to INTERRUPTED.
- Reconstruct transient runtime from current world state.
- Require explicit user Start.
- Preserve target/amount/progress only as product state.
