# M1.2 — Build and mechanically port to NeoForge 1.21.1

## Metadata

- State: PLANNED
- Milestone: M1
- Depends on: INFERRED M1.1 scheduling edge; no explicit task-level dependency
  is stated by the plan.
- Risk: high
- Sensor profiles: default, architecture_sensitive, dependency_change
- Approved plan reference: plan lines 164-172 and 185-197.

## Objective

Make the server-side Automatone path compile against the declared NeoForge
1.21.1, Java 21, and compatible NeoForge toolchain while keeping mechanical
remapping separate from behavior changes where practical.

## Why this task exists

The fork is based on a 1.20 branch, while the target is a dedicated NeoForge
1.21.1 server. The build metadata, mappings, and API signatures must be made
compatible before lifecycle and runtime ownership can be evaluated.

This task is intentionally mechanical. Runtime ownership, mixin minimization,
and native MineProcess proof remain later M1 tasks.

## Allowed scope

- Configure Minecraft 1.21.1, a compatible NeoForge 21.1.x version, and Java 21.
- Replace Fabric/Quilt Gradle plugins, metadata, dependencies, and
  initialization.
- Convert mappings/imports and repair 1.20.x to 1.21.1 registry, item, block,
  entity, world, chunk, fluid, and inventory API changes.
- Keep behavior changes separate from mechanical remapping where practical.

## Explicitly forbidden / out of scope

- M1.3 runtime-ownership removal as an untracked redesign.
- M1.4 mixin audit or native MineProcess runtime proof.
- Client rendering, HUDs, commands, schematica, fake-player behavior, or
  unrelated MineFortress features.
- Wholesale upstream merges or cherry-picks.
- Worker, quantity, GUI, networking, or product mining work.
- GUI work before Milestone 3 passes.
- Treating the plan's historical Implemented note as acceptance evidence.

The full global architecture contract, quantity semantics, and excluded-feature
list are preserved in INDEX.md.
